# Defect Log

Defects and requirement gaps identified during Phase 5 verification are recorded below. A PASS retest means the named automated/system test passed on the current build; it does not imply unrelated functionality is complete.

| ID | Severity | Summary | Cause | Fix / required action | Retest result | Evidence / status |
|---|---|---|---|---|---|---|
| SEC-01 | High | Service operations did not consistently enforce authenticated caller role and ownership. | Services accepted actor/resource IDs without mandatory authorization checks. | Inject mandatory `IAuthorizationPolicy` into all four services and check active role, enrolment, course responsibility and department responsibility before writes. | PASS — SQLite-backed negative authorization tests pass; denied operations leave records unchanged. | `tests/unit/security/SQLiteAuthorizationPolicyTest.cpp`; `ctest` security cases. **Closed.** |
| V-01 | High (assessment integrity) | Submissions more than three days late were rejected, contrary to UC01/SRS which says late work is stored and assigned zero after three days. Console marking also applied only a 10%-per-day cap, producing a non-zero mark after day 3. | SubmissionService threw before persistence; console marking capped the percentage penalty but calculated it against the raw mark rather than subtracting 10% of the assignment maximum per day. | Accept and persist late submission; calculate daily deductions against maximum mark, and assign zero when `days_late > 3` in both service strategy and console workflow. | PASS — 4+ days late stored; service and real-console tests verify final mark 0 and penalty fraction 1.0. | `WorkflowIntegrationTest.FourDaysLateSubmissionIsStoredAndReceivesZeroAfterMarking`; `ConsoleWorkflowSystemTest`. **Closed.** |
| V-02 | Medium | Resubmission overwrote the current file reference without retaining previous attempt history as described in Phase 2 UC01 and Phase 3 data dictionary. | No submission-attempt history table or insertion path existed. | Add `submission_attempts` history table and append each attempt transactionally; keep `submission_files` as latest-attempt pointer. | PASS — first and second attempts retained with attempt numbers and file references; transaction tests pass. | `WorkflowIntegrationTest.ResubmissionPreservesEarlierAttemptHistory`; `SubmissionServiceTest.ResubmissionUpdatesExistingRecordAndFileReference`; schema `submission_attempts`. **Closed.** |
| DB-01 | Medium | Active-session write failure had not been exercised through the console. | Earlier evidence only covered startup failure and a service-level constraint exception. | Add a disposable-database console system test with a trigger that aborts file metadata insertion; verify no false success and no partial rows. | PASS — application reports the failure; submissions, submission_files and submission_attempts remain empty. | `tests/system/ConsoleWorkflowTest.py` / `ConsoleWorkflowSystemTest`. **Closed.** |
| FUNC-01 | Medium | Administrator user-account update operation is not implemented although FR-03 includes create, update, deactivate and view. | `AdminService` and admin menu provide create/deactivate/view but no update operation. | Implement update operation and add authorization, validation, persistence and acceptance tests. | NOT RETESTED — outstanding implementation gap. | AT-01 is partial. **Open.** |
| ARCH-01 | Medium | Console marking and moderation logic is partly implemented as SQL in `main.cpp` instead of consistently using the Phase 3 service layer. | Presentation layer contains duplicated workflow logic; services are tested separately but not used for every console action. | Route console marking/moderation through `MarkingService` and `ModerationService`; retain repository and policy injection. | NOT RETESTED — outstanding architecture alignment gap. | Phase 3 layered design; `src/main.cpp`, `src/service/MarkingService.cpp`, `src/service/ModerationService.cpp`. **Open.** |
